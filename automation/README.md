# Googleフォームからの自動投稿セットアップ

スタッフがGoogleフォームに投稿すると、自動でこのサイト(`data/materials.json`)に
追加され、GitHub Pagesへ公開されます。GitHubのアクセストークンを個人で用意する
必要はなく、フォームに入力するだけで投稿できます。

## 全体の流れ

```
Googleフォーム回答(資料・動画ファイルを直接アップロード)
   → 連携するGoogleスプレッドシートに自動で行が追加される
   → スプレッドシートの Apps Script が「フォーム送信時」に自動起動
   → アップロードされたファイルの共有設定を「リンクを知っている全員が閲覧可」に変更
   → そのファイルへの共有リンクを data/materials.json に追加(GitHub API経由)
   → GitHub Pages が自動で再デプロイ
```

資料・動画の実体ファイルはGitHubにはコピーせず、アップロード先のGoogleドライブに
そのまま置かれます(動画は容量が大きくGitHubに向かないため)。サイト側は
既存のGoogle Drive埋め込み表示の仕組みでそのまま再生・プレビューします。

## 1. GitHubのアクセストークンを発行する

1. GitHubで自分のアイコン → **Settings → Developer settings → Personal access tokens
   → Fine-grained tokens** を開く
2. **Generate new token**
   - Repository access: **Only select repositories** → `tanpopo-seminar`(このリポジトリ)を選択
   - Permissions → **Contents** を **Read and write** に設定
   - 有効期限はお好みで(更新の手間を減らすなら長め、セキュリティ重視なら短め)
3. 発行されたトークン(`github_pat_...`)をコピーしておく
   (**このページを閉じると二度と表示されません**。安全な場所に一時保存してください)

## 2. Googleフォームを作る

以下の質問を作成する。質問文は**前方一致**で判定しているので、説明文を
括弧書きで付け足すなど多少の言い回しの変更をしても問題ない(例:「タグ」
→「タグ(検索しやすくするために…)」でもOK)。ただし「資料ファイル」で
始まる質問が2つあるので、動画用の質問には**必ず「動画」という文字**を
含めること(下記の表記を参考にしてください)。

| 質問 | 種類 | 必須 |
|---|---|---|
| タイトル | 記述式 | ✅ |
| 実施日 | 日付 | 任意 |
| 登壇者・講師 | 記述式 | 任意 |
| カテゴリ | プルダウン(下記の8種類) | ✅ |
| タグ | 記述式(カンマ区切りで複数可) | 任意 |
| 概要 | 段落 | 任意 |
| 投稿者 | 記述式 | 任意(サイトに【投稿者:○○】と表示されます) |
| 資料ファイル(写真やPDF) | ファイルのアップロード(複数可) | 任意 |
| 資料ファイル(動画) | ファイルのアップロード(**1個までに設定**) | 任意 |

「資料ファイル(写真やPDF)」は複数枚まとめてアップロードでき、サイトの
詳細画面で前へ/次へとめくって見られます。「資料ファイル(動画)」は
質問の設定で**アップロード数の上限を1個**にしてください(スクリプトは
複数アップロードされても先頭の1件しか使いません)。

カテゴリのプルダウンの選択肢(サイトの絞り込みタブと合わせる):

```
小出セミナー
秋葉塾
その他入力関連
インプラント
その他歯科治療関連
DH関連
口腔機能関連
その他
```

「資料ファイル(写真やPDF)」に写真(画像ファイル)をアップロードした場合は、
Googleドライブの汎用プレビュー(ズームアイコンなどが出て見づらい)ではなく、
サイト側で画像そのものを大きくきれいに表示するよう自動で判定しています。

「ファイルのアップロード」の質問は、フォームの設定で回答者がGoogleアカウントで
ログインしている必要がある旨が表示されます(院内のGoogleアカウントで運用する
分には問題ありません)。アップロードされたファイルは、Googleフォームの仕様上
フォーム所有者のGoogleドライブ内に「(フォーム名) (ファイルの回答)」という
フォルダが自動生成され、その中に保存されます。定期的に整理したい場合は、
このフォルダの中身を専用フォルダへ移動しても、サイト側の共有リンクは
変わらないので問題ありません(共有ドライブへ移動する場合はリンクを再取得
してください)。

## 3. スプレッドシートと連携する

フォームの「回答」タブ → 緑色のスプレッドシートアイコン →
「新しいスプレッドシートを作成」で連携する。

## 4. Apps Scriptを設定する

1. 連携したスプレッドシートを開く → メニューの **拡張機能 → Apps Script**
2. デフォルトの `Code.gs` の中身を全部消して、このリポジトリの
   `automation/google-form-to-github.gs` の中身を貼り付ける
3. 左側の歯車アイコン「プロジェクトの設定」→ 一番下「スクリプト プロパティ」で
   以下を追加する(**コードには直接書かない**)

   | プロパティ | 値 |
   |---|---|
   | `GITHUB_TOKEN` | 手順1で発行したトークン |
   | `REPO_OWNER` | `andominami` |
   | `REPO_NAME` | `tanpopo-seminar` |
   | `DRIVE_BACKUP_FOLDER_ID_MATERIAL` | (任意・下記参照) 資料(写真・PDF)の移動先にする共有ドライブのID |
   | `DRIVE_BACKUP_FOLDER_ID_VIDEO` | (任意・下記参照) 動画の移動先にする共有ドライブのID |

### マイドライブの容量を圧迫しないようにする(推奨)

アップロードされたファイルは何もしないとフォーム所有者の**マイドライブ**に
どんどん溜まっていきます。共有ドライブ(Shared Drive)に自動で移動したい場合:

1. Googleドライブで、資料(写真・PDF)用・動画用にそれぞれ共有ドライブ(またはその中のフォルダ)を作る
2. それぞれを開いた状態のURL(`https://drive.google.com/drive/u/1/folders/`の後ろの文字列)をコピーする
3. スクリプトプロパティに `DRIVE_BACKUP_FOLDER_ID_MATERIAL`(資料用)・`DRIVE_BACKUP_FOLDER_ID_VIDEO`(動画用)としてそれぞれのIDを追加する

これを設定しておくと、投稿されたファイルの共有設定を変更した直後に自動で
それぞれのドライブへ移動され、マイドライブの容量は消費しなくなります。
設定しない場合は、これまでどおりマイドライブ内の自動生成フォルダに残り続けます。
資料用・動画用のどちらか一方だけ設定することもできます。

4. 上部の「時計」アイコン(トリガー)→ **トリガーを追加**
   - 実行する関数: `onFormSubmit`
   - イベントのソース: `スプレッドシートから`
   - イベントの種類: `フォーム送信時`
   - 保存時にGoogleアカウントの権限承認を求められるので許可する
     (Googleドライブの共有設定を変更する必要があるため、Driveへのアクセス許可も
     求められます。院内利用の範囲であれば許可して問題ありません)

## 5. 権限(認証スコープ)を確認する

「共有設定に失敗」「共有ドライブへの移動に失敗」といったエラーが実行ログに出て、
かつエラー内容に `ACCESS_TOKEN_SCOPE_INSUFFICIENT` や
`insufficient authentication scopes` と書かれている場合、Googleドライブへの
書き込み権限(スコープ)が不足しています。以下の手順で直します。

1. Apps Scriptエディタの ⚙️(プロジェクトの設定)を開き、「\"appsscript.json\" マニフェスト
   ファイルをエディタに表示する」にチェックを入れる
2. 左側のファイル一覧に出てくる `appsscript.json` を開き、`oauthScopes` という項目を
   (なければ)追加する。既存の内容は消さず、以下のように `oauthScopes` を足す:

   ```json
   {
     "timeZone": "Asia/Tokyo",
     "dependencies": {},
     "exceptionLogging": "STACKDRIVER",
     "runtimeVersion": "V8",
     "oauthScopes": [
       "https://www.googleapis.com/auth/spreadsheets",
       "https://www.googleapis.com/auth/drive",
       "https://www.googleapis.com/auth/script.external_request"
     ]
   }
   ```

3. 保存する
4. `google-form-to-github.gs` に戻り、上部の関数選択プルダウンで
   **`authorizeDriveAccess`** を選んで **実行**する
5. 「承認が必要です」という画面が出るので、アカウントを選択 →
   「このアプリは Google で確認されていません」と出たら「詳細」→
   「(プロジェクト名)に移動(安全ではないページ)」→ 内容を確認して **許可**
6. 実行後にエラーが出ても、権限の確認・許可自体はその前に完了しているので問題ない

## 5.5 スマホ等で「アクセス権がありません」と出る場合(共有ドライブの設定)

PCでは見られるのに、共有ドライブのメンバーではない端末・アカウント(スマホなど)
だと写真や動画で「アクセス権がありません」と出る場合、共有ドライブ
(セミナー写真・セミナー動画)への移動後に行っている「リンクを知っている全員が
閲覧可」への変更が失敗しています。これは共有ドライブ自体の設定で、
メンバー以外への共有がブロックされていることが原因であることが多いです。

**直し方:**

1. Googleドライブで対象の共有ドライブ(セミナー写真・セミナー動画それぞれ)を開く
2. ドライブ名の右にある ▽ をクリック →「共有ドライブの設定」を開く
3. 以下を確認・変更する
   - 「共有ドライブのメンバーではないユーザーとの共有」→ **許可する**
   - 「共有ドライブ外のユーザーに付与できるアクセスレベル」→
     少なくとも **閲覧者** を含むレベルまで許可する
4. 上記を2つの共有ドライブ両方で行う

設定を直したら、`google-form-to-github.gs` の関数選択プルダウンで
**`backfillPublicPermissions`** を選んで手動実行する。これは今まで投稿された
全ファイルに対してもう一度「リンクを知っている全員が閲覧可」への変更を
やり直す復旧用の関数(何度実行しても安全)。実行後、「実行数」の実行ログで
成功・失敗件数を確認できる。失敗が残る場合は、共有ドライブの設定が
まだ反映されていないか、Google Workspace自体で外部共有が組織全体で
禁止されている可能性があるため、管理者に確認する。

今後の新規投稿分は、共有ドライブの設定さえ直っていればフォーム投稿時に
自動で正しく共有されるようになる。

## 6. テストする

実際にフォームから1件テスト投稿してみて、数分後に
https://andominami.github.io/tanpopo-seminar/ に反映されているか確認する。
写真・動画ファイルが、指定した共有ドライブに実際に移動されているかも
Googleドライブ側で確認する。

うまく反映されない場合は、Apps Scriptエディタの左側「実行数」から
エラーログを確認できます(GitHubトークンの権限不足、質問名の表記ゆれ、
権限不足によるアップロードファイルの共有設定失敗などがよくある原因です)。

## 資料の削除・修正について

Googleフォームは「追加」専用の仕組みです。登録済みの資料を削除・修正したい
場合は、このリポジトリを操作しているClaudeのチャットに頼んでください。
GitHubの操作に慣れている場合は `data/materials.json` を直接編集しても
構いません。
